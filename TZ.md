# Техническое задание  
## Разработка desktop-приложения для создания графических мемов

## 1. Общие сведения

### 1.1. Название продукта
**SupaMe** — рабочее название desktop-приложения для создания графических мемов.

### 1.2. Назначение приложения
Приложение предназначено для создания мемов путем компоновки изображений, добавления текстовых подписей, комиксных пузырей / speech bubbles и последующего экспорта готового изображения.

### 1.3. Формат приложения
Приложение должно быть реализовано как desktop-приложение с веб-интерфейсом.

Целевая модель работы:

1. Пользователь запускает приложение как обычную desktop-программу.
2. Приложение поднимает локальный сервис / backend.
3. Интерфейс открывается в обычном браузере по адресу `http://127.0.0.1:PORT`.
4. Пользователь работает в браузере как с веб-редактором.

Допускается альтернативная упаковка в Electron / Tauri, если пользовательский сценарий будет сохранен: приложение должно восприниматься как desktop-решение и открывать веб-интерфейс в браузере или встроенном браузерном окне.

### 1.4. Платформы
Поддержка целевых ОС:

- Windows 10/11 x64;
- macOS 12+;
- Linux desktop, предпочтительно Ubuntu 22.04+.

Приоритетные платформы для MVP:

- Windows;
- macOS.

Linux — по остаточному принципу, если не увеличивает сложность сборки.

---

## 2. Цель разработки

Создать удобное приложение для быстрого создания мемов:

- загрузить изображения;
- разместить их на холсте;
- добавить текст;
- добавить подпись сверху / снизу;
- добавить комиксный bubble;
- настроить внешний вид текста и баббла;
- экспортировать готовый мем в PNG / JPG / WebP;
- сохранить проект для дальнейшего редактирования.

---

## 3. Термины и сокращения

| Термин | Значение |
|---|---|
| Мем | итоговое изображение, созданное пользователем |
| Холст | рабочая область фиксированного размера |
| Проект | редактируемый документ со всеми объектами и настройками |
| Объект | любой элемент на холсте: изображение, текст, баббл |
| Слой | объект на холсте с порядком отображения |
| Bubble | комиксный пузырь для текста с хвостиком или без него |
| Caption | текстовая подпись, обычно сверху или снизу мема |
| Шаблон | заранее подготовленный макет с областями для замены |
| Локальный backend | серверная часть, работающая на компьютере пользователя |

---

## 4. Основные пользовательские сценарии

### 4.1. Создание мема с нуля
1. Пользователь запускает приложение.
2. Открывается браузер с интерфейсом приложения.
3. Пользователь создает новый проект.
4. Выбирает размер холста или пресет.
5. Загружает одно или несколько изображений.
6. Размещает изображения на холсте.
7. Добавляет текст, подпись или bubble.
8. Редактирует содержимое и оформление.
9. Экспортирует результат в изображение.

### 4.2. Редактирование ранее сохраненного проекта
1. Пользователь открывает список проектов.
2. Выбирает нужный проект.
3. Приложение восстанавливает холст, объекты, текст и настройки.
4. Пользователь продолжает редактирование.

### 4.3. Создание мема по шаблону
1. Пользователь выбирает шаблон.
2. Приложение создает проект на основе шаблона.
3. Пользователь заменяет текст и / или изображения.
4. Экспортирует результат.

## 5. Функциональные требования

## 5.1. Запуск и рабочее окно

### 5.1.1. Запуск приложения
Приложение должно:

- запускаться как обычное desktop-приложение;
- стартовать локальный сервис при необходимости;
- автоматически открывать интерфейс в браузере по умолчанию;
- показывать пользователю сообщение, если браузер не удалось открыть автоматически.

### 5.1.2. Локальный адрес
Интерфейс должен быть доступен по адресу вида:

```text
http://127.0.0.1:PORT
```

где `PORT` выбирается автоматически из свободных портов.

### 5.1.3. Поведение при повторном запуске
Если приложение уже запущено:

- не создавать несколько конфликтующих экземпляров;
- открыть уже запущенный экземпляр или переиспользовать его локальный сервис.

### 5.1.4. Минимальный интерфейс запуска
В первом запуске допускается минимальный экран:

- логотип;
- статус запуска;
- кнопка «Открыть в браузере»;
- кнопка «Выход» или «Остановить сервис».

---

## 5.2. Интерфейс редактора

### 5.2.1. Общая структура интерфейса
Интерфейс должен быть рассчитан на десктопное использование и содержать:

1. Верхнюю панель:
   - новый проект;
   - открыть проект;
   - сохранить;
   - отменить / повторить;
   - экспорт;
   - настройки.

2. Левую панель:
   - загрузка изображений;
   - шаблоны;
   - добавление текста;
   - добавление бабблов;
   - список слоев / объектов.

3. Центральную область:
   - холст;
   - zoom;
   - перемещение по холсту при необходимости.

4. Правую панель:
   - свойства выбранного объекта;
   - настройки текста;
   - настройки изображения;
   - настройки баббла;
   - настройки холста.

5. Нижнюю строку состояния:
   - размер холста;
   - масштаб;
   - статус сохранения;
   - подсказки.

### 5.2.2. Адаптивность интерфейса
Минимальная поддерживаемая ширина окна:

- 1280 px — основной целевой режим;
- 1024 px — минимально допустимый режим с упрощением панелей.

Приложение не должно требовать мобильной адаптации в MVP.

### 5.2.3. Язык интерфейса
Базовый язык интерфейса:

- русский.

Желательно предусмотреть возможность локализации:

- русский;
- английский.

---

## 5.3. Проект и холст

### 5.3.1. Создание нового проекта
Пользователь должен иметь возможность создать новый проект.

При создании можно выбрать:

- пустой холст;
- пресет размера;
- пользовательский размер.

### 5.3.2. Пресеты размеров холста
Должны быть минимум следующие пресеты:

| Название | Размер |
|---|---:|
| Квадрат | 1080 × 1080 |
| Портрет | 1080 × 1350 |
| История / сторис | 1080 × 1920 |
| Ландшафт | 1200 × 630 |
| Пользовательский | задается вручную |

### 5.3.3. Пользовательский размер
Пользователь должен иметь возможность задать:

- ширину;
- высоту;
- цвет фона.

Ограничения:

- минимальный размер: 100 × 100 px;
- максимальный размер: 4096 × 4096 px.

### 5.3.4. Фон холста
Поддерживается:

- сплошной цвет;
- прозрачный фон;
- изображение-фон, если пользователь назначил изображение как фон.

### 5.3.5. Масштабирование холста
Пользователь должен иметь возможность:

- увеличивать / уменьшать отображение холста;
- вписывать холст в экран;
- устанавливать масштаб 100%.

Диапазон отображения:

- от 25% до 400%.

---

## 5.4. Работа с изображениями

### 5.4.1. Добавление изображений
Пользователь должен иметь возможность добавлять изображения:

- через диалог выбора файла;
- перетаскиванием в окно браузера / на холст.

### 5.4.2. Поддерживаемые форматы
Минимально:

- PNG;
- JPEG;
- WebP.

Дополнительно для импорта:

- GIF — только первый кадр в MVP;
- SVG — растрируется или отображается как изображение, если браузерная реализация это позволяет.

### 5.4.3. Отображение изображения на холсте
Каждое изображение является отдельным объектом и должно поддерживать:

- перемещение мышью;
- масштабирование за угловые маркеры;
- сохранение пропорций при масштабировании по умолчанию;
- поворот;
- отражение по горизонтали;
- отражение по вертикали;
- изменение порядка слоев;
- удаление;
- дублирование.

### 5.4.4. Трансформации
Для изображения должны быть доступны:

- позиция по X / Y;
- ширина и высота;
- масштаб;
- угол поворота;
- прозрачность;
- flip horizontal;
- flip vertical.

### 5.4.5. Обрезка изображений
В MVP необходимо предусмотреть базовую обрезку изображения:

- пользователь выбирает область обрезки;
- изображение обрезается до выбранной области;
- операцию можно отменить через undo.

Допускается реализация обрезки как отдельного модального окна.

### 5.4.6. Фильтры изображений
В минимальной версии поддерживаются:

- яркость;
- контраст;
- насыщенность.

Дополнительно желательно:

- размытие;
- черно-белый фильтр;
- сепия.

Если это увеличивает срок разработки, фильтры могут быть перенесены во второй этап.

### 5.4.7. Ограничения по размеру файлов
Рекомендуемые ограничения:

- один загружаемый файл — до 20 МБ;
- суммарный объем изображений в проекте — до 100 МБ.

При превышении ограничения приложение должно показать понятную ошибку.

## 5.5. Объекты и слои

### 5.5.1. Типы объектов
Приложение должно поддерживать следующие типы объектов:

1. Изображение.
2. Текстовый объект.
3. Bubble / комиксный пузырь.
4. Группа объектов, если реализована группировка.

### 5.5.2. Панель слоев
Панель слоев должна отображать:

- список объектов;
- порядок объектов;
- тип объекта;
- миниатюру или текстовое имя;
- видимость объекта;
- блокировку объекта при необходимости.

### 5.5.3. Управление слоями
Пользователь должен иметь возможность:

- выбрать объект в списке слоев;
- изменить порядок слоев;
- поднять объект выше;
- опустить объект ниже;
- поместить на передний план;
- поместить на задний план;
- скрыть / показать объект;
- заблокировать / разблокировать объект;
- удалить объект;
- дублировать объект.

### 5.5.4. Выделение объектов
Поддерживается:

- выделение одного объекта кликом;
- выделение нескольких объектов через Shift или рамку выделения;
- снятие выделения кликом по пустой области холста.

### 5.5.5. Группировка
В MVP желательно поддержать:

- группировку нескольких объектов;
- разгруппировку.

Если это существенно усложняет разработку, группировка может быть перенесена на этап 2.

### 5.5.6. Выравнивание объектов
Необходимо поддержать базовое выравнивание:

- по левому краю;
- по горизонтали по центру;
- по правому краю;
- по верхнему краю;
- по вертикали по центру;
- по нижнему краю.

Также желательно:

- распределение по горизонтали;
- распределение по вертикали.

### 5.5.7. Привязка и направляющие
Желательно реализовать:

- привязку к краям холста;
- привязку к центру холста;
- отображение направляющих при перемещении объекта.

## 5.6. Текст и подписи

### 5.6.1. Добавление текста
Пользователь должен иметь возможность добавить:

- свободный текстовый объект;
- быструю подпись сверху;
- быструю подпись снизу;
- текст внутри баббла.

### 5.6.2. Редактирование текста
Текстовый объект должен поддерживать:

- ввод и редактирование текста;
- многострочный текст;
- перенос строк;
- ручное изменение размера текстового блока;
- автоматический перенос слов внутри границ блока.

### 5.6.3. Параметры текста
Для текста должны быть доступны:

- содержимое;
- шрифт;
- размер шрифта;
- начертание: обычный / полужирный / курсив;
- цвет текста;
- выравнивание: слева / по центру / справа;
- межстрочный интервал;
- межбуквенный интервал;
- регистр: как есть / все заглавные / все строчные;
- прозрачность.

### 5.6.4. Обводка и тень текста
Для классического вида мема необходимо поддержать:

- обводку текста:
  - цвет;
  - толщина;
- тень текста:
  - цвет;
  - смещение;
  - размытие;
  - прозрачность.

### 5.6.5. Шрифты
В приложении должен быть базовый набор шрифтов.

Минимально:

- гротескный шрифт без засечек;
- жирный мемный шрифт, аналог Impact;
- рукописный / комиксный шрифт;
- моноширинный шрифт как опциональный.

Требования к шрифтам:

- лицензия должна разрешать использование в приложении;
- шрифты должны быть встроены в приложение;
- интерфейс должен корректно отображать кириллицу.

Рекомендуется использовать открытые шрифты, например:

- Inter;
- Oswald;
- Anton;
- Roboto Condensed;
- Comic Neue;
- JetBrains Mono.

Важно: конкретные шрифты выбираются с учетом лицензии и поддержки кириллицы.

### 5.6.6. Пользовательские шрифты
В MVP возможность загрузки пользовательских шрифтов не обязательна.

Желательно во второй версии:

- загрузка TTF / OTF / WOFF / WOFF2;
- предпросмотр;
- удаление загруженного шрифта.

### 5.6.7. Автоматическое вписывание текста
Для текста внутри блока / баббла необходимо предусмотреть:

- перенос слов;
- уменьшение размера шрифта при необходимости, чтобы текст поместился;
- или предупреждение, если текст не помещается.

Рекомендуемое поведение:

- если текст не помещается, приложение автоматически уменьшает размер шрифта до минимально заданного;
- если текст все равно не помещается, показывается визуальный индикатор переполнения.

### 5.6.8. Быстрые подписи
Должны быть быстрые действия:

- «Добавить верхнюю подпись»;
- «Добавить нижнюю подпись».

По умолчанию:

- шрифт жирный, без засечек или аналог Impact;
- цвет текста белый;
- обводка черная;
- выравнивание по центру;
- текст в верхнем регистре.

Пользователь может изменить любые параметры по умолчанию.

## 5.7. Bubble / комиксные пузыри

### 5.7.1. Назначение
Приложение должно позволять добавлять комиксные пузыри для реплик персонажей или пояснений.

### 5.7.2. Типы бабблов
Минимальный набор форм:

1. Прямоугольный пузырь со скругленными углами.
2. Эллиптический пузырь.
3. Облачко / thought bubble.
4. Взрыв / shout bubble.
5. Прямоугольник без скруглений.

Желательно дополнительно:

- шестиугольник;
- выноска без пузыря, только текст с хвостиком.

### 5.7.3. Структура баббла
Каждый баббл должен состоять из:

- формы пузыря;
- текстовой области внутри формы;
- хвостика / указателя, если применимо.

### 5.7.4. Редактирование баббла
Пользователь должен иметь возможность:

- перемещать баббл;
- масштабировать баббл;
- поворачивать баббл;
- редактировать текст внутри;
- менять форму баббла;
- менять цвет фона;
- менять цвет и толщину границы;
- менять радиус скругления углов для прямоугольных форм;
- менять размер и положение хвостика;
- удалить хвостик.

### 5.7.5. Хвостик баббла
Хвостик должен быть настраиваемым.

Параметры:

- включен / выключен;
- положение на границе пузыря;
- направление;
- длина;
- ширина основания;
- изгиб / кривизна, если поддерживается;
- стиль: линия или заполненная фигура.

Минимально допускается упрощенная реализация:

- пользователь перетаскивает точку хвостика;
- форма хвостика выбирается из нескольких пресетов.

### 5.7.6. Текст внутри баббла
Текст внутри баббла должен:

- автоматически переноситься по словам;
- центрироваться по горизонтали и вертикали по умолчанию;
- поддерживать настройки шрифта, размера, цвета, начертания;
- иметь внутренние отступы.

Параметры текстовой области:

- верхний / нижний / левый / правый отступ;
- выравнивание текста;
- автоматическое уменьшение шрифта при переполнении.

### 5.7.7. Пресеты бабблов
Необходим набор пресетов:

- белый пузырь с черной границей;
- облачко мыслей;
- кричащий пузырь;
- пузырь с желтым фоном;
- пузырь с прозрачным фоном и границей.

---

## 5.8. Шаблоны

### 5.8.1. Поддержка шаблонов
Приложение должно поддерживать шаблоны мемов.

Шаблон может содержать:

- размер холста;
- фон;
- изображения;
- текстовые плейсхолдеры;
- бабблы;
- расположение объектов;
- стили текста.

### 5.8.2. Создание проекта из шаблона
Пользователь должен иметь возможность:

- просмотреть список шаблонов;
- выбрать шаблон;
- создать проект на его основе.

### 5.8.3. Редактирование шаблона
В пользовательском интерфейсе шаблоны используются только как заготовки.

Пользователь может:

- заменить текст;
- заменить изображение;
- удалить лишние объекты;
- сохранить измененный проект как обычный проект.

### 5.8.4. Импорт пользовательских шаблонов
В MVP не обязателен, но желателен.

Формат:

- JSON проекта;
- набор изображений;
- или ZIP-архив с проектом.

### 5.8.5. Встроенные шаблоны
В поставку можно включить минимальный набор встроенных шаблонов.

Требования:

- шаблоны должны быть лицензионно чистыми или использовать нейтральные заглушки;
- не использовать чужие охраняемые изображения без разрешения;
- пользователь должен иметь возможность удалить встроенные шаблоны или игнорировать их.

## 5.9. Отмена и повтор действий

### 5.9.1. История действий
Приложение должно поддерживать:

- отмену действия;
- повтор действия.

### 5.9.2. Минимальная глубина истории
Не менее:

- 50 последних действий.

### 5.9.3. Действия, которые должны попадать в историю
Как минимум:

- добавление объекта;
- удаление объекта;
- изменение позиции;
- изменение размера;
- поворот;
- изменение текста;
- изменение стиля;
- изменение порядка слоев;
- обрезка изображения;
- изменение свойств холста;
- удаление фона.

## 5.11. Сохранение проектов

### 5.11.1. Локальное сохранение
Приложение должно позволять сохранять проекты локально.

Проект должен сохранять:

- размер холста;
- фон;
- все объекты;
- порядок слоев;
- параметры объектов;
- текст;
- настройки бабблов;
- ссылки или встроенные данные использованных изображений;
- дату создания;
- дату последнего изменения;
- превью проекта.

### 5.11.2. Автосохранение
Приложение должно выполнять автосохранение:

- при изменениях, с задержкой 1–3 секунды;
- или не реже чем раз в 10 секунд;
- при закрытии вкладки / приложения, если браузер позволяет перехватить событие.

### 5.11.3. Список проектов
Пользователь должен видеть список проектов:

- название;
- превью;
- дата изменения;
- размер холста;
- действия: открыть, переименовать, дублировать, удалить.

### 5.11.4. Экспорт / импорт проекта
Желательно поддержать:

- экспорт проекта в файл;
- импорт проекта из файла.

Формат:

- JSON;
- или ZIP, содержащий JSON и ресурсы.

Если используется JSON без ZIP, изображения могут быть вложены в проект в base64.

# 6. Нефункциональные требования

## 6.1. Производительность

### 6.1.1. Скорость запуска
Целевые показатели:

- запуск локального сервиса — не более 3 секунд на типовом компьютере;
- открытие интерфейса в браузере — не более 3 секунд после запуска сервиса.

### 6.1.2. Работа редактора
Интерфейс должен оставаться отзывчивым при:

- не менее чем 20 объектах на холсте;
- не менее чем 10 изображениях размером до 4096 px по большей стороне.

### 6.1.3. Рендеринг
Операции перемещения, масштабирования и выделения должны выполняться плавно, без заметных задержек, на среднем настольном компьютере.

---

## 6.2. Надежность

Приложение должно:

- не терять данные проекта при аварийном закрытии браузера, если сработало автосохранение;
- корректно восстанавливать последний сохраненный проект;
- не повреждать файлы проектов при обычной работе;
- делать безопасное сохранение, при котором прерывание записи не приводит к полной потере данных, если это реализуемо на уровне выбранной технологии.

---

## 6.3. Безопасность

### 6.3.1. Локальный доступ
Локальный сервис должен:

- слушать только `127.0.0.1` или `localhost`;
- не быть доступным из внешней сети;
- не требовать открытия портов наружу.

### 6.3.2. Доступ к данным
Данные пользователя должны храниться:

- локально на устройстве;
- в директории приложения;
- без обязательной отправки на внешние серверы.

### 6.3.3. Отсутствие телеметрии
В базовой версии приложение не должно собирать и отправлять пользовательские данные без явного согласия.

Если добавляется телеметрия или аналитика, она должна быть:

- отключена по умолчанию;
- описана в документации;
- включается только добровольно.

---

### 6.4.1. Браузеры
Основные браузеры:

- Google Chrome последней версии;
- Microsoft Edge последней версии;
- Mozilla Firefox последней версии.

Дополнительно:

Поддержка:

- 1920 × 1080 — основной режим;

- 100%;
- 125%;
- 150%.

Приложение должно быть рассчитано на пользователя без специальных графических навыков.

# 7. Рекомендуемая архитектура

## 7.1. Общая схема

```text
+-----------------------+
| Desktop launcher/app  |
+-----------+-----------+
            |
            | запускает
            v
+-----------+-----------+
| Local backend service |
| http://127.0.0.1:PORT |
+-----------+-----------+
            |
            | отдает фронтенд и API
            v
+-----------+-----------+
| Browser frontend SPA  |
+-----------------------+
```

## 7.2. Frontend

Рекомендуемый стек:

- React или Vue 3;
- TypeScript;
- Vite;
- HTML5 Canvas через одну из библиотек:
  - Konva.js;
  - Fabric.js;
  - или аналогичную.

Рекомендация:

- для реактивного интерфейса удобен Konva.js + React Konva;
- если нужна более готовая объектная модель, можно использовать Fabric.js.

Фронтенд должен быть собран как статическое веб-приложение и открываться в браузере.

## 7.3. Backend

Backend выбирается разработчиком, но для данного ТЗ рекомендуется:

- Node.js 20+;
- Fastify или NestJS;
- TypeScript;
- SQLite или better-sqlite3;
- локальное файловое хранилище.

Альтернативно допускается:

- Python FastAPI;
- Go;
- Rust;
- .NET.

Главное требование к backend:

- работать локально;
- не требовать обязательного интернета;
- хранить данные пользователя на устройстве.

## 7.4. Упаковка desktop-приложения

Возможные варианты:

### Вариант A. Локальный сервер + браузер
Рекомендуемый для формулировки «открывается в обычном браузере»:

- исполняемый файл запускает локальный сервер;
- открывает браузер по адресу `127.0.0.1:PORT`;
- приложение поставляется как установщик или портативная сборка.

Плюсы:

- полноценный веб-фронтенд;
- обычный браузер;
- проще отладка.

Минусы:

- менее «нативное» ощущение;
- нужно аккуратно управлять процессом и портом.

### Вариант B. Electron / Tauri
Допускается, если интерфейс все равно реализован как web frontend.

Плюсы:

- более цельный desktop-опыт;
- легче управлять окном, файлами, системным треем.

Минусы:

- если используется встроенное окно, это не совсем «обычный браузер»;
- больше размер дистрибутива.

Для соответствия исходной формулировке рекомендуется вариант A или гибридный вариант, когда приложение может открываться и в системном браузере.

# 10. Локальный API

```http
GET /api/health
```

Проверка доступности сервиса.

```http
GET /api/version
```

Получение версии приложения.

## 10.2. Проекты

```http
GET /api/projects
```

Список проектов.

```http
POST /api/projects
```

Создать проект.

```http
GET /api/projects/:id
```

Получить проект.

```http
PATCH /api/projects/:id
```

Обновить проект.

```http
DELETE /api/projects/:id
```

Удалить проект.

```http
POST /api/projects/:id/duplicate
```

Дублировать проект.

## 10.3. Ресурсы

```http
POST /api/assets
```

Загрузить изображение / шрифт / ресурс.

```http
GET /api/assets/:id
```

Получить файл ресурса.

```http
DELETE /api/assets/:id
```

Удалить ресурс.

## 10.4. Шаблоны

```http
GET /api/templates
```

Список шаблонов.

```http
POST /api/templates
```

Импорт шаблона.

```http
DELETE /api/templates/:id
```

Удалить шаблон.

## 10.5. Экспорт проекта

Опционально:

```http
POST /api/projects/:id/export
```

Сформировать файл экспорта проекта.

- Canvas: Konva.js или Fabric.js.

# 22. Итоговое краткое описание продукта

**SupaMe** — desktop-приложение с веб-интерфейсом, которое запускается локально, открывается в обычном браузере и позволяет создавать мемы из изображений, текстовых подписей и комиксных бабблов. Пользователь может загружать изображения, размещать их на холсте, добавлять текст и пузыри, настраивать стиль, сохранять проекты локально и экспортировать готовый мем в PNG / JPG / WebP.
